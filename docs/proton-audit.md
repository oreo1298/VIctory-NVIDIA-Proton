# Proton / Wine audit

What can break, or run slower, when the Windows `victory.exe` runs under Wine with
vkd3d-proton (D3D12 on Vulkan), DXVK's DXGI and dxvk-nvapi, on an NVIDIA GPU. The target is
proton-cachyos or GE-Proton (both on Valve's Proton 10 tree), CachyOS, an RTX 4090 and a recent
proprietary driver. This is not a native Linux port. Every Proton-only behaviour is gated at
run time on `victory_core::wine::is_wine()`, and `VICTORY_PROTON=0|1` overrides it. Windows
behaviour is unchanged.

Sources read for this audit (2026-11-27): this tree; Wine master (`dlls/ntdll/unix/virtual.c`,
`system.c`, `dlls/kernelbase/memory.c`); vkd3d-proton master (`README.md`,
`libs/vkd3d/device.c`); vkd3d master (`libs/vkd3d-shader/hlsl.y`, `hlsl.c`); DXVK master
(`dxgi_adapter.cpp`, `dxgi_interfaces.h`, `dxvk.conf`). Line numbers are of this tree before the
Proton work.

How to read the status column:

- **fixed**: changed in this branch, behind a Wine-only path where behaviour must differ.
- **logged**: the run now measures it or says what it found; no behaviour change.
- **launcher**: handled by `scripts/play-nvidia.sh` (environment, paths, checks).
- **docs**: written up in `docs/linux-proton.md`; nothing to change in code.
- **open**: needs the RTX 4090 to decide.

Likelihood: **H** = expected to hit on the first run, **M** = plausible, **L** = unlikely or
only off the default path.

## 4. What was checked under Wine here

Wine 9.0 (Ubuntu), Linux 6.18, no GPU; the cross-compiled test binaries and `victory.exe`:

- `victory.exe --help`, `config` (Unix paths become `Z:\…`) and `hlsl-check` run.
- The Wine detection and its log line; the write-watch test reports signal-based write watches
